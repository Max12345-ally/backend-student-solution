# Решения и понимание

## B0: инструменты и деньги

**Дата:** 2026-10-05  
**Проблема:** подготовить воспроизводимый Python-проект и точно считать деньги в упражнении.

**Варианты:** использовать `float` или `Decimal`; оставить версии инструментов плавающими или зафиксировать их.

**Выбор:** Python 3.13, Pytest, Ruff и Mypy с точными версиями в `requirements.lock`; деньги считаются только через `Decimal`.

**Причина:** `float` хранит десятичные дроби приблизительно, поэтому может дать артефакт. Lock-файл фиксирует не только названия библиотек, но и конкретные версии, из-за чего повторная установка воспроизводима.

**Проверяемый сценарий:** `2 × 100.10 + 1 × 20.20 = 220.40`; отрицательное количество вызывает `InvalidQuantityError` до выдачи итоговой суммы.

**Ограничения:** факт выполнения команд и отдельного ревью фиксируется только после реального запуска. B1–B6 пока не реализованы.

## B1: внешний HTTP API

**Проблема:** безопасно читать и изменять учебный каталог через HTTP.

**Выбор:** `httpx.Client` живёт внутри `with`; Pydantic отделяет JSON-парсинг от проверки схемы; `Decimal` используется для цены. Ошибки HTTP-статуса, сети, timeout, JSON и схемы представлены разными исключениями.

**Причина:** успешный статус 200 не доказывает, что тело является корректным JSON нужной структуры. Timeout POST не доказывает, что сервер не создал товар: ответ мог потеряться после выполнения операции, поэтому автоматического повтора нет.

**Фактическая проверка:** живой DummyJSON: GET/PUT/DELETE вернули 200, POST — 201. Контролируемые тесты проверили пустую страницу, 404/500, timeout, ConnectError, битый JSON, неверную цену и закрытие клиента.

**Ограничение:** DummyJSON имитирует изменения; созданный товар не обязан появиться в следующем GET.
